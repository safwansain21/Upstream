# Upstream Implementation Plan

> Execution: use executing-plans inline, with a persistent acceptance ledger and final independent branch review.

**Goal:** Build the full report-first investigation application specified by the supplied bundle.

**Architecture:** Next.js frontend and same-origin API proxy, FastAPI domain service, Supabase Auth/PostGIS/private storage, PostgreSQL leased workers. Exact Python scientific package consumes immutable snapshots; no UI, AI or simulator dependencies.

**Tech stack:** Required PRD §10 stack; current compatible stable versions pinned in lockfiles.

**Spec:** ../../specification/UPSTREAM-PRD.md, ../../specification/SCIENTIFIC-ENGINE.md, ../../specification/ACCEPTANCE.md. Audit: ../../specification-audit.md.

## Global constraints

- Numeric scientific JSON values are decimal strings, unknown is null, and origins are real/synthetic/replayed.
- Authentication and organization capabilities are server-enforced; administrator is not scientific expert.
- SAT and UNKNOWN retain possibilities; only proven UNSAT may exclude under reviewed eligibility.
- No production protocol gets fixture bounds. No live external integration success without actual configuration.
- Preserve the primary orange/ice-blue references, specified fonts, organic major boundaries, AA accessibility and all listed viewports.
- Acceptance checklist is authoritative; only run checks can be marked PASS.

## Review focus

Revocation during sync; approval/dependency races; overlapping bookings; unknown topology/compute failure; signed artifact and predecessor tampering. Tests belong to tasks 2, 6, 7 and 9 as appropriate.
